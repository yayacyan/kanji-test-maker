# 漢字テストメーカー：小3「はると」視点の用紙評価

前提：我是 AI 在模擬小學生視角，不是真的孩子。本報告刻意區分兩類：
- 【實測】：用 Chrome 印刷模擬（print media）→ PDF，量 CSS 變數 `--f`、`.cell` `.box` 的 getBoundingClientRect（1mm=3.78px），並用 PyMuPDF 檢查 PDF 內向量框的實際尺寸（結果一致：cell 6.0mm 的 PDF 內框為 5.82mm＋線寬）。
- 【推測】：「小三生大概會這樣覺得」的模擬，沒有真人驗證。

檢查用檔案在 `$SP/review/child/`：`g3_mix10.pdf/png`（小3・10問）、`t_kaki|yomi|sentence|mas|free`（各5問）、`m_*`（版面矩陣）、`g1_mix10`、`g6_mix10`、`g3_tiers2`、`gen.py`（產生腳本）。
（PNG 我改用 PyMuPDF 以 100〜500dpi 輸出，因為 `sips` 只有 72dpi，字太糊看不出線與格。）

## 3. 題型ごと（各5問）に最初に戸惑う点

| 題型 | 見た目 | はるとが最初に戸惑う点 |
|---|---|---|
| 書き問題 | ひらがなに縦線、左にマス | 【推測】線の意味（「この言葉を漢字に」）が説明なしでは分からない。マスの数が答えの字数（送りがな込み）だと気づかないと「向かって」の「かって」を書かずに止める子がいる。 |
| 読み問題 | 漢字に縦線、左にマス | 【推測】書きと見た目が同じ。線がひらがなか漢字かだけが違い。交互に並ぶので「今どっち？」と毎回止まる。 |
| 例文穴埋め | 文中に□□、右に小さい「てんいん」 | 【推測】□の右の小さいひらがなを「ここに書く答え」と勘違いしそう。実際は「読みのヒント→□に漢字」。また□の中に直接書くので、5問版で□7.3mm、10問版で5.3mm と小さい【実測】。 |
| 練習マス | 大きな漢字＋（読み）＋マス5つ | 【推測】「なぞる？　写す？　何回？」が不明。1字の語は5マス＝5回、2字の語（お宮）は5マス＝2回半、3字は1回半…で、どう写すのか決まっていない。マスは十字補助線付き（画面上）。 |
| 自由入力 | 「「守る」をつかって、文をつくりましょう。」＋縦線1本 | ここは指示文があるので、意味は分かる。ただし書く場所は「左にある1本の線」だけで、【実測】書ける幅は約5.5mm（10問版）〜8mm（5問版）しかない。【推測】3年生の手書き（1字8〜10mm）だと1文字がやっと。線の長さが問題ごとに違う（50〜135mm）。 |

「ひらがなに引かれた線」：縦書きの右側に引く正しい形。ただし説明がないので【推測】「かざりの線？」と思う子もいる。
「四角と小さいふりがな」：例文穴埋めの項を参照。
「読みのマスと書きのマス」：見た目が全く同じ（同じ2mm十字補助線付きマス）。区別できるのは線が引かれた語がひらがなか漢字かだけ。

## 4. 良かった点

1. 【実測】縦書き・右から左・番号は丸囲み数字（①②…）で、各問の右上に必ずある。問題の区切りは薄いグレーの縦線。学校のテストに近く、見て怖くない。
2. 【実測】マスの数＝答えの字数（送りがな込み、ひらがなは1字1マス）。ヒントになり、「何字書く？」が分かる。
3. 【実測】小1の用紙はひらがな中心（例：「りんごがいつつある。」）、小6は法律・憲法・鋼鉄など学年相応の語。学年で難易度がちゃんと変わる。
4. 【実測】名前・点数欄が上にあり、右下にアプリ名だけで余計な装飾がない。
5. 【実測】5問版・A3横10問では文字が大きく（18.7pt／23.8pt）マス8.3〜10.5mm。読みやすさは良い。
6. 【実測】50問でも文字が枠からはみ出すことはなかった（overflow=0）。長文は折り返し、次の行が同じ枠内に収まる。

## 6. 指示文がないことは、子どもにとってどれだけ問題か

- 【実測】用紙には題名（「漢字テスト」）・問題数（「10問」）・名前・点・番号・線・マスしかなく、問題の種類や答え方を書いた文はゼロ。自由入力だけが問題文の中に指示を含む。
- 【推測】学校でふだんのテストなら、先生が「①〜④は漢字で、⑤〜⑧は読みがな」と口頭で説明する前提。その説明がある教室なら問題は小さいが、家庭学習・宿題・保護者が作って渡す場合は、はると（説明がないと指示を読み飛ばす）が最初のマスで止まる可能性が高い。
- 【推測】特に「書き」と「読み」が交互に並ぶ設定（初期値）が厳しい。ふつうの漢字テストは書きのまとまり→読みのまとまりの順に並ぶので、毎問切り替えるのは子どもの負担が大きい。
- 影響の大きさ：高（改善提案1）。

## 7. 縦書き・右から左・番号・次の問題への進み方

- 【実測】1段目は右端の①から左へ。①〜⑩の丸数字は各列の右上。10問1段のときは迷わない。
- 【推測】学校の縦書きテストに慣れている前提なら、この方向はすんなり入る。
- 【実測】2段以上（20問以上）は、点線で段が分かれ、次は下の段の右端から。段が変わる所には矢印や説明はない。
- 【実測】番号は、10問A4縦で直径5.0mm・数字は約9.5pt。読みやすい。50問では直径3.6mm・数字6.7ptで小さい。
- 【実測】問題どうしの区切りは0.2mmの薄いグレーの線だけ。折り返しがある長文（30〜50問）ではこの線がないと2行目がどの問題か分かりにくい。

## 8. 学年別（小1・小6）

【小1】（`g1_mix10`）
- 【実測】文字は4.8mm（13.6pt）・マス6.0mm。1年生は文字が大きく書く（12〜15mmが目安）ので、マス6mmは特に小さい【推測】。
- 【実測】文は「りんごがいつつある。」「ノートになまえをかく。」「手をあらってからごはんをたべる。」など、ひらがな中心で1文20字以内。読めそう。
- 【推測】「線が引かれたいつつ→五つ」の意味は、1年生には説明なしだとほぼ分からない。読みの問題「日」（きょうは、たのしい日だった→ひ）は「にち／び」と迷う余地あり。
- 【推測】縦書きに慣れていない1年生（横書きの学習が先）には、縦書き自体が最初の壁。
【小6】（`g6_mix10`）
- 【実測】「社会科見学でさいばんしょに行った。」「日本国憲法は、国の大切なきまりだ。」「この橋は鋼鉄でできている。」など、1文が最長20字前後、語は法律・尊敬・鋼鉄など6年の配当漢字。学年相応。
- 【推測】文字4.8mm・マス6.0mmは6年生でもぎりぎり。裁判所（12画＋8画＋8画…）は6mmに3字並べると窮屈。
- 【推測】「割ると」「乱れた」などの送りがな付きは、線の範囲とマス数で推理する形で、慣れた6年生なら問題なし。

## 11. 改善提案（優先度順・最大8件）

1. **書体設定のバグ修正（最優先）**：`app.js` の `buildSheet`（font-family を style 属性に入れている行）が、フォント名の二重引用符でHTML属性を壊している。クォートを `'` にするか、`style` をDOM経由で設定する。これで「教科書体」（環境にUD教科書体がなければ明朝）が初めて出る。修正後は3書体でそれぞれ用紙が変わることを確認する。
2. **指示文を入れる**：「①〜⑤ 線のひいてある ひらがなを、漢字で書きましょう。」「⑥〜⑩ 線のひいてある 漢字の 読みがなを、書きましょう。」を用紙の上に、題型ごとの短い説明を自動で入れる。書き問題／読み問題／例文穴埋め／練習マスの4つ。学年が低いほどひらがな中心で。オン・オフ可にしておくとよい。
3. **書きと読みを交互にしない（初期値）**：書き→読みの順にまとまりで並べる。または、まとまりごとに小見出し（例：「一　書き」「二　読み」）と指示文を付ける。
4. **マスを大きくする**：10問A4縦のマスを、少なくとも8〜10mmにする。自動段数を「10問→2段」にする（手動で2段にすると7.8mmになった）か、A4の文字上限 cap を上げる。30問以上は「30問はA3横をすすめる」などの案内を入れる。50問A4縦はマス4.25mmなので、小学生向けには警告が必要。
5. **例文穴埋めの小さい読みに説明を付ける**：「□の右のひらがなは読みです」と指示文で伝える。または、ヒントを□の右ではなく（かっこ）で問題文のすぐ後ろに付ける。
6. **自由入力の書く欄を広げる**：線1本ではなく、横幅を1.25em→2em以上にするか、罫線を2〜3本にする。長さが答えの長さにならないよう一定にする（例：常に最大まで）。
7. **PDFの十字補助線を安定させる**：背景のグラデーションで描くのをやめ、実線の細い線（またはSVG）にして、濃さも少し上げる。PDFビューアーで全マスに十字が出るか確認する。
8. **次の段・折り返しの案内**：段が分かれるとき、段の右端に「↓次の段へ」、または折り返す行にも問題番号の薄い印を付ける。線が2行にまたがる語は、可能なら語の途中で折り返さない。
